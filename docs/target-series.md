# 대상별 시리즈 수록과 후속 사건 연결

부대·함선은 예시이며, 조직·기관, 인물, 기술·자원, 교통수단·시설, 저술·운동도 대상별로 등록한다. 분류는 `series_categories`를 사용하며 기존 번호를 바꾸지 않는다. 사건 수록은 특정 대상의 명시된 기록 연결이다. 완성된 생애사나 인과관계 서사를 주장하지 않는다.

현재 `series.db`의 `series`와 `series_items`가 활성 연결을 저장한다. `series_candidates`에는 자료가 아직 적은 명칭도 수록한다. 추가 대상의 분류·별칭·문맥·시기·상위 대상은 `scripts/series-entity-rules.json`에서 관리한다. 각 `key`는 고정한다. `metadata.entity_series_registry`가 같은 후보/시리즈 번호를 재사용한다.

사건 자료를 추가한 후 먼저 미리보기:

```powershell
python scripts/expand-entity-series.py --root . --output _local/series-preview
```

결과를 검토하고 기존 소유자 지침에 따라 전체 프로젝트를 백업한 뒤 연결 갱신:

```powershell
npm run refresh:series
```

이 명령은 사건 본문과 event_id를 수정하지 않는다. 명칭이 등록된 대상의 새 사건을 같은 시리즈에 더하고 시간순으로 정렬한다. 최소 두 사건이 있으면 활성화한다. 하나 또는 영 건인 대상은 후보 단계에 남는다. 후보 검토 TXT는 DB 변경 직후 `ID<TAB>텍스트`로 다시 내보낸다. 반복 실행은 중복 번호·연결을 만들지 않는다.

새 대상은 규칙 파일에 고유한 key, 표시명, 기존 분류 번호, 대상 종류, 명시적인 별칭을 추가한다. 동명이인·동명 함선은 조건으로 구분한다. 수록 시기로 묶은 선박 기록은 그 기간의 기록 모음이며 동일 선박의 전체 생애를 검증했다는 의미가 아니다. 출처 파일명, URL, 검증 메모에만 등장하는 이름은 사건 대상의 근거가 아니다.

부대의 소속 관계는 등록된 포함 관계로 처리한다. 예를 들어 이지중대의 기록을 제506연대와 제101공수사단 모음에도 연결할 수 있다. 그 모음이 해당 상위 부대의 모든 활동을 포괄하는 것은 아니다.

이미 존재하는 연결은 자동 삭제하지 않는다. 규칙 변경 후에도 남은 연결을 제거해야 한다면 근거를 확인해 별도로 검토한다. 공개 자료 재생성, 테스트·빌드, 배포, 실제 페이지 확인은 기존 배포 절차를 따른다. 갱신 명령 자체는 배포하지 않는다.
